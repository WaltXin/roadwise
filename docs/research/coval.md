## 2. How it works, end to end

**Building blocks.** A simulated run combines four reusable pieces: **Agent** (who is being tested), **Persona** (who is talking), **Test Set** (what the conversation is about) and **Metrics** (how success is measured). A **Template** saves that combination so it can be relaunched or scheduled. A launch is a **run**, usually one simulated conversation per test case. Each conversation has a time cap by plan: Starter 10 min, Growth 30 min, Enterprise 60 min. [doc] [Simulations](https://docs.coval.ai/concepts/simulations/overview)

**Connecting an agent** [doc] [llms.txt](https://docs.coval.ai/llms.txt)

- Supported connections:
  - inbound and outbound phone (PSTN)
  - SIP
  - HTTP chat, chat WebSocket and A2A JSON-RPC
  - voice WebSocket
  - SMS
  - Pipecat Cloud and LiveKit
  - hosted connectors for OpenAI Realtime, Gemini Live, Grok Realtime and Deepgram Voice Agent
- Choosing SIP instead of a plain phone number lets Coval pass per-call context in headers, such as `X-Coval-Simulation-Id`, `{{test_case.account_id}}` or run metadata. [doc] [Inbound voice](https://docs.coval.ai/concepts/agents/connections/inbound-voice)
- **Vapi:** there is no dedicated connection type. Vapi appears only in the tracing wizard and in example code. [doc] [Wizard](https://docs.coval.ai/concepts/simulations/traces/wizard)
- **Retell:** not mentioned anywhere in the docs dump (`llms-full.txt`).
- [inference] Agents on Vapi or Retell are presumably tested by calling their phone number or SIP endpoint.

**Test sets** [doc] [Test sets](https://docs.coval.ai/concepts/test-sets/overview)

- A test case is one scenario. Test cases can be generated by AI, written by hand, or imported from CSV/Excel.
- There are three input types:
  - **Scenario:** the simulated user improvises toward a goal.
  - **Transcript:** it adapts to follow a reference conversation.
  - **Script:** it says the exact lines given.
- The docs recommend keeping separate "Regression" (happy-path) and "Adversarial" sets.
- Test sets are versioned, so you can tell which version a run used.
- Test cases can carry expected behavior and attributes. A beta feature, "API Simulation Wrappers," fetches fresh data before each simulation.

**Personas** [doc] [Personas](https://docs.coval.ai/concepts/personas/overview)

- Behavior settings: who speaks first, and a proactive **interruption rate** (none, or roughly every 90s, 45s or 30s).
- Silent mode, for testing dead air.
- Voice catalog, about 20 languages and accents, background noise (built-in or uploaded), and speakerphone acoustics.
- One run uses exactly one persona. The test case defines *what* the user wants; the persona defines *how* they behave.

**Agent mutations.** You can run configuration variants (prompt, model, voice, temperature, headers) next to the base agent in the same run. Results are grouped by variant for side-by-side comparison. [doc] [Mutations](https://docs.coval.ai/concepts/agents/mutations)

**Metrics** [doc] [Metrics](https://docs.coval.ai/concepts/metrics/overview)

- There are five groups:
  - **Deterministic:** regex, end reason, IVR flow adherence, match expected output, custom SQL.
  - **Statistical / audio:** latency, interruption rate, time to first audio, background noise, loop detection, and many acoustic artifact checks.
  - **ML model:** audio and transcript sentiment, timbre drift, transcription error.
  - **LLM Judge:** binary, categorical or numerical, on transcript or audio. Also composite and "Agentic" modes.
  - **Trace:** computed from OpenTelemetry spans, such as LLM/STT/TTS time to first byte, token usage, tool-call count and STT word error rate.
- Every metric runs on both simulated and uploaded conversations.
- Two definitions to note [doc] [Statistical](https://docs.coval.ai/concepts/metrics/types/statistical):
  - **Latency** is the average silence between the user finishing a turn and the agent starting to speak.
  - **Interruption Rate** counts only times the *agent* talks over the *user*, per minute. Times the user interrupts the agent are excluded.

**Production monitoring**

- Production calls come in through the API (`POST /v1/conversations/uploaded:submit`), the CLI or the UI. [doc] [Uploaded conversations](https://docs.coval.ai/concepts/uploaded-conversations/overview)
- Stereo audio is recommended (agent on channel 0, user on channel 1).
- Metrics can be re-run on historical calls. New results are added rather than overwriting old ones.
- A production failure can be turned into a test case.
- Dashboards track metrics over time.
- Alerts can watch each conversation or a whole run, and notify Slack, email or a webhook. [doc] [Alerts](https://docs.coval.ai/concepts/alerts/overview)
- Coval can ingest traces via OpenTelemetry or import them from Langfuse, Arize Phoenix and LangSmith. [doc] [Trace imports](https://docs.coval.ai/concepts/simulations/traces/imports)

**Human review.** Review projects support two kinds of work: metric labeling (comparing human and automated answers) and failure triage (by type, severity and similar categories). They include reviewer-agreement insights. The docs describe using these labels to calibrate the LLM judge. [doc] [Human review](https://docs.coval.ai/concepts/metrics/human-review/human-review)

**CI and automation**

- A GitHub Action, `coval-ai/coval-github-action@v1`, launches a run from a pull request or a manual dispatch. [doc] [GitHub Actions](https://docs.coval.ai/getting-started/github-actions-tutorial)
- Not confirmed: whether the action fails the build when a metric misses a threshold.
- Also available: a REST API, a CLI with an "agent mode" for autonomous callers, TypeScript and Python SDKs, Terraform, skills for coding agents, and an MCP "Coval connector" for ChatGPT, Claude and Codex. [doc] [llms.txt](https://docs.coval.ai/llms.txt), [Coval connector](https://docs.coval.ai/mcp/overview)

**Sofia.** Coval's in-app agent investigates results and proposes actions, which the user must confirm. Through the MCP connector it is read-only. [doc] [Sofia](https://docs.coval.ai/sofia/overview)

**STT/TTS Benchmarks.** A beta feature, enabled on request, that compares speech-to-text and text-to-speech providers on your own audio and text. [doc] [Benchmarks](https://docs.coval.ai/concepts/benchmarks/overview)

**Docs vs. marketing**

- The marketing page does not name a CI integration; only the docs do (the GitHub Action).
- The marketing site's figures are not reflected or backed up in the docs: 217% accuracy improvement, 3.1M metrics per week, "<15m to first simulation."

## 5. Comparable tools

**Hamming** ([hamming.ai](https://hamming.ai)) [claim]

- Positions itself as "the security layer for voice and chat agents."
- Three products: RedSwarm (red-teaming), GreenLoop (testing that can fail a CI build) and BlueTrace (production monitoring).
- Claims 50+ built-in metrics, 50K+ concurrent calls, 65+ languages and 95%+ agreement with human evaluators.
- Integrations: Vapi, Retell, ElevenLabs, LiveKit, Pipecat, plus SIP/PSTN/WebRTC and OpenTelemetry export.
- **Difference from Coval:** it leads with security, compliance and audit reporting.

**Cekura** ([cekura.ai](https://www.cekura.ai)), formerly Vocera; rebranded in March 2025 ([CustomerServiceManager](https://www.customerservicemanager.com/cekura-secures-2-4m-to-create-a-robust-reliability-layer-for-conversational-ai))

- YC Fall 2024. Raised a $2.4M seed in July 2025, led by YC. [Call Centre Helper](https://www.callcentrehelper.com/cekura-raises-2m-test-voice-ai-259565.htm)
- The site promotes [claim]: simulation, red-teaming, cross-platform vendor bake-offs, and production monitoring.
- It also promotes a self-improvement loop: flag an issue, reproduce it, suggest a prompt patch, re-run a release gate.
- Lists Vapi and Retell among its partners.
- **Difference from Coval:** heavier emphasis on automated fixes.

**Roark** ([roark.ai](https://roark.ai)) [claim]

- YC-backed.
- Claims 500+ metrics scored on production calls, with audio-native scoring.
- Drafts fixes from failing calls and replays them against the callers that broke.
- Integrations: Vapi, Bland, Retell, LiveKit, Pipecat and ElevenLabs.
- Publishes **Roark Live Bench**, a public leaderboard ranking voice stacks on live phone calls.
- **Difference from Coval:** strongest focus on analyzing production calls after the fact.

**Bluejay** ([getbluejay.ai](https://getbluejay.ai)) [claim]

- YC, founded 2025.
- Offers "Digital Humans" simulation, monitoring, A/B testing of prompts and flows, and the MISTT speech-to-text benchmark.
- Claims customers including Google (27 days of testing time saved per month) and DoorDash, and says it supported a campaign of 400k calls.
- No integrations are listed on the page.

**Platform-native testing** [doc]

- **Vapi:** Simulations pair a scenario with a personality, run in voice or chat mode, and are scored with structured outputs. Latency limits are enforced in voice mode only. The older Test Suites feature is being deprecated. [Vapi docs](https://docs.vapi.ai/observability/simulations-overview)
- **Retell:** simulation testing is **text-only**. All success criteria are judged together in a single LLM pass for one pass/fail verdict. A batch API can be used for CI gating. [Retell docs](https://docs.retellai.com/test/llm-simulation-testing)
- **ElevenLabs:** three test types (Simulation, Next Reply, Tool Call). Tests can be repeated 2–20 times to get a pass rate. Runnable from a CLI or API, and tests can be created from real conversations. [ElevenLabs docs](https://elevenlabs.io/docs/agents-platform/customization/agent-testing)
- [inference] These are free and quick to start. They are tied to one platform and have shallower audio metrics than the dedicated tools.

**General LLM eval and observability tools** (Langfuse, Arize Phoenix, LangSmith)

- Coval imports traces from these tools rather than replacing them. [doc] [Trace imports](https://docs.coval.ai/concepts/simulations/traces/imports)
- Braintrust's voice support was not researched.

## 6. Implications for Roadwise (all [inference])

- **Use an eval platform to run the "how to test it" step; don't compete with it.**
  - Roadwise writes the hypothesis and acceptance criteria.
  - It translates them into a test set, persona and metrics, then launches the run through the API, CLI agent mode or MCP connector.
  - Coval's agent mutations directly support "proposed change vs. current agent" comparisons.
- **Treat the customer's eval data as product-specific evidence.**
  - Before recommending that the customer act on an industry signal, query their uploaded-conversation metrics (end reason, latency, loop detection, judge results).
  - The goal is to confirm the problem the signal addresses actually appears in their calls.
  - This is the interruption example from the one-pager made concrete. Upload minutes are also much cheaper than simulation minutes.
- **Do not rebuild these.** Simulated callers, telephony and SIP connectors, audio and acoustic metrics, human review queues, dashboards and alerts. Roughly six vendors and three agent platforms already offer them.
- **Encode metric meanings in Roadwise's domain knowledge.**
  - Coval's "Interruption Rate" measures the agent talking over the user, not how well the agent handles a caller barging in.
  - Testing barge-in handling needs persona interruption settings plus a judge or trace metric.
  - Knowing which metric actually tests a hypothesis is part of Roadwise's value.
- **Keep acceptance criteria and held-out scenarios on Roadwise's side, separate from the team making the change.** Record which eval versions were used (Coval versions test sets, metrics, personas and agents) so the follow-up step is reproducible.
- **Watch for overlap.**
  - Coval's Sofia already runs scheduled investigations and posts daily briefs to Slack.
  - Cekura and Roark already draft fixes.
  - Roadwise's distinct value: the *external* industry signal, the reasoning about why it matters for this product, a log of roadmap decisions, and follow-up at the user-journey and business level, beyond eval pass rates.
- **Treat eval vendors as signal sources, labeled as leads.** Their changelogs, Roark Live Bench, Bluejay MISTT and Coval Benchmarks show where tooling and stack quality are heading.
- **For the hackathon, stay vendor-neutral.**
  - Build a thin adapter over Coval, or over the agent platform's native tests if the customer is on Vapi, Retell or ElevenLabs.
  - Retell's native tests are text-only, so they cannot test latency or audio hypotheses.
